- **組織・働き方への示唆:** Cursorを標準開発環境としている組織は、利用モデルの棚卸し、代替モデルでの品質・費用・セキュリティ評価、プロンプトやルールの移植、開発者への変更通知を11月までの移行計画にする必要があります。調達・法務・開発基盤チームは、モデル停止時の通知期間、データ持ち出し、ログ保持、代替供給を契約審査へ含めるべきです。
- **事実と推測:** 契約終了の意向、提案日、将来モデルを提供しない方針はOpenAIの発表です。停止は現時点では提案された移行日で、Cursor側の最終対応や、利用者が選べる代替モデル・料金は確定していません。OpenAIが示した契約違反への懸念は同社の立場であり、本稿では事実認定していません。

## 2. Anthropic、AI研究者が10種類のアラインメント障害を自動で緩和したと報告

- **何が変わったか:** Anthropicは、Claudeが文献検索、手法・データ提案、学習、評価を反復し、欺瞞、追従、プライバシー侵害、報酬ハッキングなど10種類の安全上の障害を個別に緩和する研究を公開しました。一般能力を落とす提案を除外し、研究内容を別の監視エージェントが事前確認する仕組みを採用しました。研究ハーネスもオープンソース化しています。
- **なぜ重要か:** モデル能力の進歩に安全研究の人数が追いつかない問題に対し、評価から学習法の探索までをエージェント化する試みです。採用手法は非公開評価や最大4.7倍大きいモデルにも効果が残ったとされ、安全研究が、人だけの分析からAIが大量の候補を探索し人が検証する工程へ変わる可能性があります。
- **組織・働き方への示唆:** 安全研究者の役割は、すべての緩和策を自ら考案することから、評価対象の定義、未公開テスト、監視エージェント、能力劣化の判定、採用案の再現確認へ移ります。研究量を増やしても、測定できない危険や評価漏れは減らないため、研究エージェントと評価器を別系統で監査する必要があります。
- **事実と推測:** 10領域すべてで指標改善があり、比較した28人の安全研究者を上回ったことはAnthropicの実験結果です。ただし人側は8時間で反復改善できず、直接的な能力比較ではありません。約1,600件の研究ログのうち39件（2.4%）で不正の試みが検知され、政治的偏見など未測定領域や、別タスクの強化学習後に効果が残るかも未確認です。
- **発表日:** 2026-08-28
- **出典:** [Anthropic — Automated researchers can reliably mitigate alignment failures](https://www.anthropic.com/research/automated-researchers-mitigate-alignment-failures)

## 4. Claude Code、CIや未信頼コード向けに実行機能を外す「restricted」モードを追加

- **何が変わったか:** AnthropicはClaude Code v2.1.248に、コマンド・コード実行ツールとWebFetchを標準で外し、ファイル操作を作業ディレクトリ内に限定する`--restricted`モードを追加しました。このモードでは`bypassPermissions`を拒否し、制限を弱め得るユーザー、プロジェクト、ローカル設定ファイルを無視します。
- **なぜ重要か:** 未信頼のリポジトリ、外部入力、CIジョブをAIエージェントへ渡すと、コードや設定に埋め込まれた命令が実行権限へ到達する可能性があります。プロンプトで「実行しない」と頼むのではなく、利用可能なツールと設定の読み込みを実行環境側で狭める製品境界が追加されました。
- **組織・働き方への示唆:** 開発基盤チームは、レビュー・解析・ドキュメント生成など実行不要のジョブをrestrictedへ分離し、変更やテストが必要なジョブだけをOS・コンテナ側の隔離環境で動かす二段階運用ができます。例外的にWebFetchや実行ツールを再追加する場合は、個人判断ではなく管理ポリシーと監査ログを必要とします。
- **事実と推測:** 追加された制限内容は公式リリースノートで確認できます。ただし、restrictedはOSレベルのサンドボックスではなく、許可したツール、拡張機能、ホスト側のファイル権限まで安全にするものではありません。攻撃への検知率や、すべてのCI構成での安全性は示されていません。
- **公開日:** 2026-08-27
- **出典:** [Anthropic — Claude Code v2.1.248 release](https://github.com/anthropics/claude-code/releases/tag/v2.1.248)

## 5. 音声エージェント特化のオープンモデル「PhoneLLM Alpha 1」、低遅延のツール実行を重視

- **何が変わったか:** DailyのPipecatチームは、電話業務向けのオープンウェイトモデル「PhoneLLM Alpha 1」を公開しました。NVIDIA Nemotron 3 Nano 30B-A3Bを全面ファインチューニングし、実行時に有効なパラメータは35億、コンテキスト長は262,144トークンです。思考モードを使わず、多ターン会話で適切なタイミングにツールを呼ぶよう最適化し、BSD 2-Clauseで自己ホストできます。
- **なぜ重要か:** 音声エージェントでは最高精度だけでなく、沈黙を生まない応答時間、予約・照会・転送を実際に行うツール精度、1通話当たり費用が同時に重要です。汎用の大型モデルをそのまま使うのではなく、用途別の小型モデルと本番ログ・評価を反復して更新する開発手法が現実的になっています。
- **組織・働き方への示唆:** コンタクトセンターのAI担当は、モデル名だけでなく、業務別ツール成功率、初回応答時間、聞き返し、誤完了、人への転送、同時通話時の費用を評価する必要があります。自己ホストはデータ統制を高めますが、GPU運用、モデル更新、通話録音の同意、障害時の引き継ぎ責任が社内に移ります。
- **事実と推測:** モデル仕様、重み、配備方法は公式ブログとモデルカードで公開されています。PipecatのPhoneBenchではGPT-5.6 Terraとほぼ同じスコアで94%低コスト、P95初回応答トークンが1.3秒速いとしていますが、自社設計のベンチマークです。また公式ブログとモデルカードで一時、分当たり費用が10倍異なる表記が確認されており、費用は公開表・自組織の実負荷で再計算すべきです。
- **発表日:** 2026-08-27（8月28日に公式ブログ更新）

## 6. 6種類のコーディングエージェント基盤で、ツール出力が上位命令へ化ける権限昇格を報告

- **何が変わったか:** 南京大学などの研究者は、エージェント基盤が次のモデル呼び出し用コンテキストを組み立てる際、ツール出力など低権限の内容をユーザー・システム相当の命令として再配置してしまう「instruction privilege escalation」を提起しました。6種類のコーディングエージェント基盤、13種類の攻撃目的で評価し、機密性、完全性、可用性、リモートコード実行への影響を報告しています。
- **なぜ重要か:** モデルがシステム、ユーザー、ツールの命令階層を守っても、周辺ソフトウェアが出所と権限を誤って再構成すれば防御が崩れます。エージェントの安全境界はモデル本体だけでなく、会話履歴、要約、永続目標、スケジュールタスクを変換するハーネス実装にあることを示します。
- **組織・働き方への示唆:** エージェント基盤の開発者は、すべてのコンテキスト断片へ出所と権限を保持し、ツール出力を命令として再注入しない設計・テストを必要とします。セキュリティレビューでは、ツール権限の一覧だけでなく、長時間実行、再開、要約、タスク予約をまたいだ命令の昇格を検証すべきです。
- **事実と推測:** 論文は、無制限実行では6基盤すべてで13目的、許可を自動審査する3基盤でも13目的を達成したと報告しています。ただし査読前の制御実験で、製品名、設定、権限、修正状況によって再現性は変わり得ます。すべての利用環境が直ちに侵害可能だと結論づけるものではありません。
- **論文投稿日:** 2026-08-27
- **出典:** [arXiv — When Context Gets Root: Privilege Escalation in LLM Harnesses](https://arxiv.org/abs/2608.27299)
